h1. DateTimeNormalizer handler configuration

This handler reads one or several date/datetime fields, accepts them in any of the supported ISO 8601 formats (see [#Supported input formats]), normalizes them to a single point in time (UTC) and rewrites them using the {{output_format}} you choose.

It is used when consumers send the same field in different formats, for example:
* {{"sndDt": "2026-03-06"}}
* {{"sndDt": "2026-03-06T12:05:20.480Z"}}

Both values are normalized and written back in the same output format.

----

h2. List of keywords

||Keyword||Mandatory||Description||
|{{path}}|Yes|Path of the field to normalize. Segments are separated by {{/}}. Use {{*}} to process *every element of a list* (see [#Wildcard]).|
|{{output_format}}|No|Format of the outgoing date. Any [Java DateTimeFormatter pattern|https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html#patterns]. Default: {{yyyy-MM-dd'T'HH:mm:ss.SSS'Z'}}|
|{{timeZonePath}}|No|Path, in the same message, of a field containing a time zone id (e.g. {{Europe/Paris}}). Used only for input values *without* an offset. Default: {{Europe/Paris}}|

{note}No {{input_format}} is needed: the handler detects the format automatically among the [#Supported input formats].{note}

----

h2. Wildcard

{{*}} in {{path}} means "every element of this list".

||Path||Fields processed||
|{{payload/sndDt}}|The single field {{payload.sndDt}}|
|{{payload/sndgDts/*/sndDt}}|{{sndDt}} in *each* element of the {{payload.sndgDts}} list|

----

h2. Time zone rules

The time zone is only used when the input value has *no offset*.

||Input value||Time zone used||
|Has an offset ({{Z}}, {{+02:00}}, {{-05:00}}...)|The offset in the value. {{timeZonePath}} is ignored.|
|No offset, {{timeZonePath}} configured|The time zone read at {{timeZonePath}}|
|No offset, no {{timeZonePath}}|{{Europe/Paris}}|

A date without time (e.g. {{2026-03-06}}) is midnight in the time zone used.

{note}With {{Europe/Paris}}, {{2026-03-06}} becomes {{2026-03-05T23:00:00.000Z}} in UTC (the previous day at 23:00, or 22:00 in summer).{note}

----

h2. Supported input formats

||Format||Example(s)||
|{{yyyy-MM-dd}}|{{2026-03-06}}|
|{{yyyy-MM-ddXXX}}|{{2026-03-06Z}}, {{2026-03-06+02:00}}|
|{{yyyy-MM-dd'T'HH:mm}}|{{2026-03-06T14:30}}|
|{{yyyy-MM-dd'T'HH:mmXXX}}|{{2026-03-06T14:30Z}}, {{2026-03-06T14:30+02:00}}|
|{{yyyy-MM-dd'T'HH:mm:ss}}|{{2026-03-06T14:30:00}}|
|{{yyyy-MM-dd'T'HH:mm:ssXXX}}|{{2026-03-06T14:30:00Z}}, {{2026-03-06T14:30:00+02:00}}, {{2026-03-06T14:30:00-05:00}}|
|{{yyyy-MM-dd'T'HH:mm:ss.S}} (1 to 9 decimals)|{{2026-03-06T14:30:00.1}}, {{2026-03-06T14:30:00.123}}, {{2026-03-06T14:30:00.123456789}}|
|{{yyyy-MM-dd'T'HH:mm:ss.SXXX}} (1 to 9 decimals)|{{2026-03-06T14:30:00.123Z}}, {{2026-03-06T14:30:00.123+02:00}}|

*Offset ({{XXX}}) can be:* {{Z}} (UTC), {{±HH:mm}} (e.g. {{+02:00}}) or {{±HH:mm:ss}} (e.g. {{+02:00:00}}).

h3. Rejected input formats

||Input||Reason||
|{{2026-03-06T14}}|Hour without minutes|
|{{2026-03-06T14:30:00+02}}|Offset without minutes|
|{{2026-03-06T14:30:00+0200}}|Offset without colon|
|{{2026-03-06 14:30:00}}|Space instead of {{T}}|
|{{2026-03-06t14:30:00z}}|Lowercase {{t}} / {{z}}|
|{{20260306}}, {{20260306T143000Z}}|Compact format without separators|
|{{2026-11}}, {{2026-W47-5}}, {{2026-324}}|Year-month, week date and ordinal date|
|{{2026-03-06T14:30:00.1234567890Z}}|More than 9 decimals|

----

h2. Output format

{{output_format}} accepts any Java {{DateTimeFormatter}} pattern.

||output_format||Output for {{2026-03-06T14:30:00.123Z}}||
|{{yyyy-MM-dd'T'HH:mm:ss.SSS'Z'}} (default)|{{2026-03-06T14:30:00.123Z}}|
|{{yyyy-MM-dd'T'HH:mm:ss.SSSZ}}|{{2026-03-06T14:30:00.123+0000}}|
|{{yyyy-MM-dd}}|{{2026-03-06}}|

{warning}{{'Z'}} (with quotes) writes the letter Z. {{Z}} (without quotes) writes the offset as {{+0000}}.{warning}

----

h2. Example

h3. Configuration

{code:language=js|title=Configuration}
{
  "input": {
    "file": {
      "path": "./modified-events.txt",
      "endOfLine": "\n"
    }
  },
  "parse": {
    "json": {}
  },
  "format": {
    "json": {}
  },
  "handle": [
    {
      "dateTimeNormalizer": {
        "path": "payload/paymentEngineRunningData/sndgDts/*/sndDt",
        "output_format": "yyyy-MM-dd'T'HH:mm:ss.SSS'Z'",
        "timeZonePath": "/header/technical/timeZone"
      }
    },
    {
      "dateTimeNormalizer": {
        "path": "payload/businessPaymentInformation/othrDts/*/othrDt",
        "output_format": "yyyy-MM-dd'T'HH:mm:ss.SSS'Z'",
        "timeZonePath": "/header/technical/timeZone"
      }
    }
  ]
}
{code}

h3. Input

{code:language=js|title=Input}
{
  "header": {
    "technical": { "timeZone": "Europe/Paris" }
  },
  "payload": {
    "paymentEngineRunningData": {
      "sndgDts": [
        { "sndDt": "2026-03-06" },
        { "sndDt": "2026-03-06T14:30:00" },
        { "sndDt": "2026-03-06T14:30:00+02:00" },
        { "sndDt": "2026-03-06T14:30:00.123Z" }
      ]
    }
  }
}
{code}

h3. Output

{code:language=js|title=Output}
{
  "header": {
    "technical": { "timeZone": "Europe/Paris" }
  },
  "payload": {
    "paymentEngineRunningData": {
      "sndgDts": [
        { "sndDt": "2026-03-05T23:00:00.000Z" },
        { "sndDt": "2026-03-06T13:30:00.000Z" },
        { "sndDt": "2026-03-06T12:30:00.000Z" },
        { "sndDt": "2026-03-06T14:30:00.123Z" }
      ]
    }
  }
}
{code}

||Input||Rule applied||Output||
|{{2026-03-06}}|Date only, no offset: midnight Europe/Paris|{{2026-03-05T23:00:00.000Z}}|
|{{2026-03-06T14:30:00}}|No offset: Europe/Paris (UTC+1 in March)|{{2026-03-06T13:30:00.000Z}}|
|{{2026-03-06T14:30:00+02:00}}|Offset in the value|{{2026-03-06T12:30:00.000Z}}|
|{{2026-03-06T14:30:00.123Z}}|Already UTC|{{2026-03-06T14:30:00.123Z}}|
